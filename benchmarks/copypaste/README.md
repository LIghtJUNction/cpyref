# 复制粘贴 Benchmark（CopyPaste Benchmark）

版本：0.1.0。目录名：`benchmarks/copypaste`。

本基准分别回答两个问题：工具是否按要求搬运原文；真实 Agent 在有、无 cpyref 时是否更准确、更省时、更省模型费用。这两个问题不能用同一组数据替代。

**当前交付是可运行的工具层对照实验。真实模型实验尚未运行，模型 Token、费用和成功率为未测量，不是零。** 结果位于 `results/<GitHub run ID>/`。每次运行的报告、原始记录和安装证据保留在独立目录，不用后一次结果覆盖前一次。

## 1. 先安装最新 Git 版本，再测试

CI 先通过 `git ls-remote` 解析当时最新的 `main` 提交，再执行：

```sh
cargo install --git https://github.com/LIghtJUNction/cpyref --rev "$SHA" --locked --root "$INSTALL_ROOT"
```

使用安装目录中的绝对二进制路径，不调用 PATH 中可能残留的旧版本。另检出同一个 SHA，作为真实文件来源和 Rust 验证目标。记录源提交、Cargo.lock 摘要、二进制摘要、脚本摘要、安装命令和日志、版本、操作系统、CPU、Rust/Python 版本及 CI 运行链接。测试前安装的版本在整批测试中固定；测试期间主分支后续更新不会静默改变被测软件。

Cargo 官方说明 `--git`、`--rev` 和 `--locked` 的语义：[cargo install](https://doc.rust-lang.org/cargo/commands/cargo-install.html)。锁定依赖是为了重现这次安装，不声称使用所有依赖的最新版本。

## 2. 对照组不能被故意削弱

| 组 | 实际执行策略 | 解释范围 |
|---|---|---|
| `cpyref` | 真正执行已安装的 copy、paste；必要时追加通用 Python 写入步骤 | 当前固定调用方案的效果 |
| `python_bytes` | 直接读写字节，严格选择；需要跨阶段保留时用临时文件和摘要；允许一次写入多个目标 | 有能力编写正确脚本的无 cpyref 对照，不强制重写原文 |
| `inline_base64` | 选择内容后无损编码到 stdout，再经 stdin 传给写入程序 | 正文往返的机制消融，不模拟 LLM，不注入转写错误 |
| `native_cp` | 整文件任务直接使用系统 cp | 常见原生命令参考，仅限适用任务，不含快照完整性和 fsync 保证 |

Python 子进程使用 `-I -S`，避免用户启动脚本和 site 初始化造成不相关开销。Python 方案的选择和写入程序作为真实 `-c` 参数执行，不假设已经为 Agent 安装了另一个剪贴板软件。

`inline_base64` 不实现项目/组隔离和快照损坏检测。这三项明确记为 unsupported，不伪装成通过，也不拿它们制造 cpyref 的胜率优势。原生 cp 不参加不适用的任务。比较正确率必须使用共同支持的任务集；比较流程成本必须同时说明持久快照、完整性验证和进程数量等差别。

## 3. 真实任务怎样建立

任务以“输入材料、用户目标、允许修改的位置、最终验收”定义，而不是以“必须调用哪个命令”定义。原始材料、目标原文和无关文件在任何组开始前固定。参考答案由生成器单独构造，不交给被测命令。

### 已运行的材料层级

R01—R06 使用被测提交的真实仓库文件：原 MIT 许可证、中文 Agent 文档、Cargo 配置、Rust 源码、README 章节，以及 README 一次复制写入十个目标。这是**真实文件材料上的任务重放**，不是从生产用户会话采样得到的操作分布。

S01—S29 是由固定随机种子和明确字节值构造的工作流程。材料可公开重建，没有真实密钥、客户代码或私有聊天。它们不是随机制造错误的假 Agent。

| 覆盖面 | 任务 |
|---|---|
| 长内容与特殊字节 | 4 KiB 参数长链接、引号与 shell 字符、中文与组合字符、CRLF、无末尾换行、256 KiB 二进制、1 MiB 文件、64 字节小文件、stdin |
| 定位 | 行号、命名正则分组、起止标记、上下文消歧、重叠匹配、无匹配、错误正则、空内容 |
| 目标操作 | 新文件、十个目标、禁止覆盖、授权替换整个文件、符号链接保护 |
| 粘贴扩展 | 在唯一标记前插入、替换标记间区域、追加、重复目标标记时拒绝修改 |
| 状态与协作 | 原文件删除、原文件改写、同项目子目录、其他项目拒绝、其他组拒绝、明确共享、保存数据损坏 |

Linux 下共 35 个独立任务。Windows 不创建需要额外权限的符号链接测试，不能把跳过的平台任务计为通过。**本轮正式性能实测仅在 Linux CI 上执行，不借用项目已有三平台单元测试冒充三平台基准结果。**

插入、局部替换、追加及目标歧义使用 `cpyref copy → paste 到临时片段文件 → Python 执行目标编辑`。结果标注 `cpyref_native=false`。这是“有 cpyref 的完整工作流程”，不能证明原生 paste 已实现这些编辑功能。将来原生接口加入后应新增 native treatment，保留当前组合流程作对照。

### 下一步加入真实用户轨迹

获得授权后，从实际开发会话随机采样复制需求，保留复制前的仓库提交、源文件、目标文件和用户目标。先去除密钥及私有内容，再由独立人员验证目标字节与允许修改范围。按文件大小、编码、重复次数、项目数量、目标操作、是否需要多 Agent 交接分层采样。记录来源和排除原因，不仅挑选 cpyref 擅长的长文本。

同一仓库、相同模板及近重复片段必须归为同一组，整体分入开发集或保留测试集，不能把轻微改写的同一道题同时放两边。发布的 35 项任务是开发/回归集，不是已经保密的泛化测试集。

还应分开四类入口：文件、可管道读取的工具输出、具有可取回句柄的工具响应、仅存在于聊天消息里的原文。当前测试覆盖文件和 stdin。仅在聊天中的长链接，若宿主没有提供消息导出或原文句柄，cpyref 不会凭空读取到它；不能把预先偷偷写入文件的条件当成这个场景已解决。

## 4. 验收条件

成功任务必须满足完整字节一致、所有目标正确、源文件按约定保持或变更、无关项目哨兵和项目标记未变、不产生未授权文件。使用字节比较和 SHA-256 记录，不用“语义大致相同”替代准确复制。

拒绝任务必须满足预期退出码、目标不被修改；cpyref 原生命令还须返回有效 JSON 错误代码，且 stdout 不泄漏正文。`AMBIGUOUS`、`NO_MATCH`、`REF_NOT_FOUND`、损坏和覆盖拒绝是正确行为，不算成功复制，也不能算错误失败。

工具验收率和正常复制成功率分别解释。35 项中包含正常任务与故意要求拒绝的任务；20 次重复只用于观察稳定性和耗时波动，不能宣传成 700 个独立真实需求。

任务开始前准备材料，开始计时后执行选择、复制、状态变化、粘贴及必要的辅助程序，完成后才验收。每条命令 30 秒超时。程序错误、超时和验收失败都保留原始记录，不只保留成功运行。

## 5. 测量与统计

每个任务、每个适用组预热一次，随后重复 20 次。每个重复区组中随机打乱任务顺序和同题组顺序。各组使用独立临时目录、同一输入和预先固定的目标。顺序随机种子为 20261014。使用 Python 单调高精度时钟 `perf_counter_ns`：[官方说明](https://docs.python.org/3/library/time.html#time.perf_counter_ns)。

计时包括新进程启动、原文选择、复制、粘贴、必要的写盘及辅助操作；不含安装、造数据、验收、清理。没有主动清空系统缓存，因此主要是缓存已热条件下的测量。报告逐任务中位数及 p95，不用不同任务的文件大小汇总成误导性的总吞吐量。

| 指标 | 当前是否实测 | 注意 |
|---|---|---|
| 字节级结果、正确拒绝、无关文件保护 | 是 | 可确定的验收结果 |
| 总流程耗时、逐命令耗时、进程数 | 是 | 固定脚本；包含语言运行时启动差异 |
| 参数、stdin、stdout、stderr 字节数 | 是 | 进程接口流量，不是模型 Token |
| 临时快照实际文件字节数 | 是 | 不是峰值磁盘，也不含已清理临时文件 |
| 模型输入/输出/缓存/推理 Token | 否 | 需要真实模型使用记录 |
| 模型费用、规划时间、脚本生成难度 | 否 | 不能由字节数或 CLI 耗时换算 |
| 峰值内存、能耗、冷盘、崩溃恢复 | 否 | 未测量 |

同一机器的 20 次重复不能替代跨机器、跨操作系统和跨任务验证。性能结论必须带环境、版本和具体任务范围。未来真实 Agent 结果按任务做配对比较，置信区间按任务/仓库分组抽样，不能把同一题多次重试当独立样本。

## 6. 真实 Agent A/B 协议

使用完全相同的模型版本、预算、系统提示、通用读写/终端工具、工作目录材料和用户目标，开启全新会话。A 组不安装 cpyref，但允许 Python、shell、管道和临时文件；B 组额外提供已验证版本的 cpyref。不得禁止 A 组使用高效搬运方式。

工具说明占用的输入 Token 也要计费。可再设 C 组“cpyref 加配套技能”，将软件本身与技能提示的效果分开；不能只给 B 组详细步骤而不给 A 组任务信息。

每题的处理顺序随机化，先登记模型、参数、每题 5 次独立运行和固定时间/调用预算，不根据结果选择最有利的样本。不要让第二组看到第一组的解法。复制/删除源文件这类分阶段任务，宿主在相同检查点执行同一状态变化，两组都必须收到同一事件通知。

模型看得到题目及源材料，看不到参考答案、验收摘要或其他组记录。真正上线时，参考答案放在 Agent 无权读取的目录或另一个容器；仅把文件命名为 hidden 并不构成隔离。可参考 SWE-bench 将执行与评估环境明确区分的做法：[evaluation guide](https://www.swebench.com/SWE-bench/guides/evaluation/)。

主指标：限定预算内的最终准确完成率、危险误修改率。次指标：真实端到端时间、首次正确完成率、模型工具调用/重试次数、实际模型计费记录。模型 Token 必须来自实际提供方记录，分别保存输入、输出、缓存及推理字段；未知值保留 null，不使用字符数除以四，也不人为添加逐字输出延迟。

每条 Agent 结果至少包含 task_id、数据和软件 SHA、组别、模型版本、运行配置、随机种子、尝试号、起止时间、退出原因、完整工具轨迹的位置及摘要、各 Token 使用字段、费用依据、最终文件验收和无关文件变更。当前 runner 的 `agent_trials`、`model_tokens`、`model_cost` 均为 null。**本交付没有接入付费模型，没有生成任何冒充真实 Agent 测试的数据。**

## 7. 运行和证据文件

```sh
# 克隆后先安装某个已解析的主分支 SHA；把占位变量换成真实路径。
cargo install --git https://github.com/LIghtJUNction/cpyref --rev "$SHA" --locked --root "$INSTALL_ROOT"
git checkout --detach "$SHA"
python3 /path/to/benchmarks/copypaste/bench.py \
  --source "$TESTED_SOURCE" --binary "$INSTALL_ROOT/bin/cpyref" \
  --out "$RESULTS" --repeats 20 --seed 20261014
```

`--source` 必须是被测提交的检出目录；基准脚本可来自另一个包含本目录的检出。不要在没有基准文件的旧提交里寻找脚本。Windows 二进制文件名是 cpyref.exe；本轮 CI 命令针对 Linux。

`manifest.json` 记录材料、选择条件、预期状态及摘要；`raw.jsonl` 保留每次正式运行、事件、退出码、耗时和校验。每组第 0 次正式运行还保留规范化的完整命令参数，其余保留参数摘要；大正文不写入结果日志。`summary.json` 和 `REPORT.md` 从原始数据汇总。`install.log`、`environment.txt`、`paste-help.txt` 和 Rust 检查日志是额外证据。结果中的 `<workspace>` 仅替代随机临时目录前缀，不替代正文或实际执行。

工作流只自动提交结果到 `bench/copy-paste-v1`，不自动合并主分支，不删除已有结果。正式报告以安装成功且原始测试数据已保存为前提。失败安装或脚本错误必须保留并说明，不生成成功结论。
